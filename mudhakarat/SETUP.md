# مذاكراتي — تعليمات الإعداد والنشر

المشروع جاهز على Supabase باسم `bac-mudhakarat` (المنطقة eu-central-1). هذه الخطوات تتبقى عليك.

## 1) ضبط المصادقة (مرة واحدة، من لوحة Supabase)

**Authentication ← URL Configuration**
- `Site URL` = عنوان موقعك بعد النشر (مثال `https://mudhakarat.example.com/`).
- `Redirect URLs` أضف العنوان نفسه. بدونهما تفتح روابط تأكيد البريد واستعادة كلمة السر على عنوان خاطئ.

**Authentication ← Providers ← Email**
- أبقِ «Confirm email» مفعّلاً لحسابات الطلاب (يمنع التسجيل ببريد لا يملكه صاحبه).
- حدّ طول كلمة السر الأدنى: 8.

> البريد الافتراضي في Supabase محدود بعدد قليل من الرسائل في الساعة. إن سجّل صفّ كامل في يوم واحد، ضع SMTP خاصاً (Authentication ← SMTP Settings) أو وزّع التسجيل على أوقات مختلفة.

## 2) مفتاح Google AI (لحسابك أنت فقط)

1. أنشئ مفتاحاً من Google AI Studio.
2. أضفه في Supabase: **Edge Functions ← Secrets** باسم `GEMINI_API_KEY`.
   (اختيارياً: `GEMINI_MODEL`، والافتراضي `gemini-2.5-flash`.)
3. لا تضعه في أي ملف من المشروع، ولا في GitHub.

## 3) تفعيل الذكاء الاصطناعي لحسابك

بعد أن تُنشئ حسابك من التطبيق، شغّل في **SQL Editor**:

```sql
update public.profiles set ai_enabled = true
where id = (select id from auth.users where email = 'بريدك@example.com');
```

بقية الطلاب يبقى لهم `ai_enabled = false` ولا يستطيع أي أحد تغييره من التطبيق. يستوردون برنامجك كملف `.json`.

لتفعيله لزميل لاحقاً: نفس الأمر ببريده. وللجميع: `update public.profiles set ai_enabled = true;` (انتبه لحدود الخطة المجانية).

## 4) النشر

التطبيق ملفات ثابتة. ارفع محتويات المجلد كما هي (بدون `tests/` و`supabase/` إن أردت) إلى أي استضافة ثابتة تدعم HTTPS: Netlify أو Vercel أو Cloudflare Pages أو GitHub Pages.

- لا يوجد بناء (build). المجلد الجذر هو المنشور.
- HTTPS إلزامي لتثبيت التطبيق (PWA) وعمل الـ Service Worker.
- عند تغيير أي ملف، غيّر رقم `CACHE` في أول `sw.js` (مثلاً `mz-v1.0.2`) كي تتحدث النسخ المثبتة عند الطلاب.

## 5) سير العمل المقترح مع الصف

1. أنت: تسجّل الدخول، ترفع صورة/PDF برنامج الشهر في «استيراد»، تراجع القائمة وتعتمدها.
2. أنت: من «استيراد» تصدّر «ملف البرنامج» (`.json`) وترسله للصف.
3. الطالب: يسجّل حساباً، يضبط علاماته الكاملة للمواد من «الإعدادات»، ثم يستورد الملف ويعتمده.

ملف البرنامج لا يحتوي علاماتك المتوقعة أو الفعلية ولا هدفك.

## 6) ما الذي في الخلفية

- `supabase/migrations/0001_schema.sql`: الجداول وRLS والمشغّلات (مطبّق أصلاً على المشروع).
- `supabase/functions/parse-schedule/index.ts`: الدالة الخلفية (منشورة أصلاً). لإعادة نشرها: `supabase functions deploy parse-schedule --project-ref kbscvsrlbjebmzsbxnut`.

## 7) فحوص الاستلام (نُفّذت)

| الفحص | النتيجة |
|---|---|
| الجداول والربط بالمستخدم | ✓ |
| RLS: مستخدم لا يرى/يعدّل/يحذف بيانات غيره، ولا يُدرج باسم غيره | ✓ (اختبار داخل القاعدة) |
| منع تعديل `ai_enabled` من المستخدم | ✓ |
| رفض العلامة الأكبر من الكاملة أو السالبة | ✓ |
| تجاهل الكتابة الأقدم من النسخة المحفوظة | ✓ |
| حسابات المعدل الحقيقي/المتوقع/المطلوب (16 اختباراً) | ✓ |
| إدخال العلامات دون إنترنت ثم المزامنة عند العودة | ✓ (متصفح حقيقي، خادم مُحاكى) |
| لا أخطاء JavaScript في المتصفح | ✓ |
| تنبيهات Supabase الأمنية | لا شيء |

لم يُختبر من هذه البيئة (الشبكة محجوبة): تسجيل حساب فعلي، وقراءة صورة بالذكاء الاصطناعي، وتثبيت التطبيق على هاتف حقيقي. اختبرها بعد النشر بحسابك أولاً.
